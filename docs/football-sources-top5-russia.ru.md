# Источники данных для топ‑5 европейских лиг + Россия

## Цель документа

Собрать практичный shortlist источников по футбольным новостям и матчевой статистике для:
- Английской Премьер-лиги (EPL)
- Ла Лиги (Испания)
- Серии A (Италия)
- Бундеслиги (Германия)
- Лиги 1 (Франция)
- РПЛ / Кубков РФ (Россия)

С фокусом на 3 канала ingestion:
1. RSS (предпочтительно, стабильно и дешево)
2. HTML scraping (fallback, когда RSS/API нет)
3. Match stats API / structured feeds (результаты, таблицы, расписание)

---

## 1) Резюме по стратегии

### Что брать в первую очередь
1. **Новости:** RSS как основной канал (минимальный риск и поддержка provenance).
2. **Матчи/результаты:** отдельный статистический API (а не парсинг новостей).
3. **HTML scraping:** только как fallback и только для источников с допустимой политикой.

### Почему так
- RSS проще поддерживать и дешевле в эксплуатации.
- HTML-структуры ломаются чаще всего.
- Результаты матчей и таблицы надежнее брать из специализированных API.

## 2) Топ‑5 + Россия: источники новостей

## EPL (Англия)

### RSS (рекомендуется)
- BBC Sport Football (общий футбол, EPL покрывается широко).
- Sky Sports Football / Premier League разделы (если доступен RSS у раздела).
- Goal.com (по разделам/языкам, при наличии feed).

**Оценка:** высокий приоритет для RSS-агрегации, хорошая регулярность публикаций.

### HTML scraping (fallback)
- Официальные клубные сайты EPL (у многих нет удобного RSS по всем рубрикам).
- Точечный парсинг разделов «News» у лиги/клубов.

**Риск:** средний/высокий — разная верстка и антибот-защита.

### Где брать результаты/статистику
- Football-Data.org (fixtures/results/standings, coverage зависит от плана).
- API-Football (RapidAPI) — очень широкое покрытие.
- Sportradar/Stats Perform (enterprise-уровень, дорого, но надежно).

---

## La Liga (Испания)

### RSS
- Marca / AS / Mundo Deportivo (если есть рабочие feeds разделов fútbol).
- ESPN FC (международное покрытие, RSS при наличии).

**Оценка:** можно собрать устойчивый пул испаноязычных и англоязычных лент.

### HTML scraping
- Локальные спортивные медиа Испании, если по нужной теме RSS отсутствует.

**Риск:** средний — частые изменения DOM и paywall-блоки у отдельных изданий.

### Статистика и результаты
- Football-Data.org
- API-Football
- Understat (xG, advanced metrics; чаще через неофициальные обертки)

---

## Serie A (Италия)

### RSS
- Gazzetta dello Sport / Corriere dello Sport / Tuttosport (проверять доступность feed по секциям).
- Международные англоязычные агрегаторы (ESPN/Goal) для бэкапа.

**Оценка:** рабочий микс италоязычных + международных фидов.

### HTML scraping
- Итальянские издания (fallback).

**Риск:** средний, особенно при сильной рекламной обвязке страницы.

### Статистика
- Football-Data.org
- API-Football
- Opta/StatsBomb (если нужна продвинутая аналитика и есть бюджет)

---

## Bundesliga (Германия)

### RSS
- Kicker / Sport1 / DW Sports (при наличии стабильных RSS).
- Международные источники для подстраховки.

**Оценка:** умеренно высокий потенциал RSS, но важно проверять стабильность feed.

### HTML scraping
- Официальные клубные сайты и локальные немецкие медиа.

**Риск:** средний.

### Статистика
- Football-Data.org
- API-Football
- FBref (structured tables, но аккуратно с ToS)

---

## Ligue 1 (Франция)

### RSS
- L’Équipe / RMC Sport / France Football (если feed доступны).
- Eurosport FR (по секциям при наличии RSS).

**Оценка:** приемлемо для контентного потока, но ленты нужно регулярно health-check’ить.

### HTML scraping
- Французские спортивные медиа с нестабильными/отсутствующими RSS.

**Риск:** средний/выше среднего (динамический контент, paywall).

### Статистика
- Football-Data.org
- API-Football
- Soccerway (исторически полезно, но скрапинг с осторожностью)

---

## Россия (РПЛ и кубковые турниры)

### RSS
- Чемпионат (если есть релевантные RSS-потоки по футболу/РПЛ).
- Sports.ru (проверять доступность feed по разделам/тегам).
- Матч ТВ / Sport-Express (при наличии RSS в нужных разделах).

**Оценка:** ключевой регион, стоит иметь минимум 2–3 резервных источника.

### HTML scraping
- Чемпионат, Sports.ru, Sport-Express, клубные сайты РПЛ (fallback).

**Риск:** средний, но высокие преимущества локального контента на русском.

### Статистика
- API-Football / Football-Data.org (если покрытие РПЛ устраивает).
- Ручной fallback-парсинг официальных протоколов/календарей (только как резерв).

## 3) Оценка каналов ingestion

## RSS
**Плюсы:**
- Низкая стоимость поддержки.
- Прозрачный provenance (URL, дата, источник).
- Быстрое масштабирование на десятки источников.

**Минусы:**
- Не у всех медиа есть feed.
- Иногда урезанный контент (тизеры без полного текста).

**Итог:** основной канал для MVP.

## HTML scraping
**Плюсы:**
- Можно закрыть пробелы, где нет RSS/API.
- Доступ к полному тексту и дополнительным полям.

**Минусы:**
- Высокая стоимость поддержки.
- Юридические и технические риски (ToS, anti-bot, частые поломки).

**Итог:** только как fallback и с контрактом качества.

## Stats API
**Плюсы:**
- Структурированные данные (fixtures/results/standings/events).
- Надежность выше, чем у HTML-парсинга.

**Минусы:**
- Часто платные планы и rate limits.

**Итог:** обязательно в базовой архитектуре отдельно от новостного ingestion.

## 4) Рекомендуемый стек источников для старта (MVP)

## Новости
- 8–12 RSS-лент (по 1–2 на лигу + 2–3 для России).
- 2–3 HTML-коннектора только там, где RSS не хватает.

## Матчи/результаты
- 1 основной API-провайдер (например, API-Football).
- 1 резервный API (например, Football-Data.org).
- Fallback парсер официальных календарей только для критических дыр.

---

## 5) Quality gates для production

1. **Source Health:**
   - SLA по источнику: % успешных обновлений за 24ч.
   - alert при 3+ подряд фейлах.

2. **Content Quality:**
   - дедупликация по title+time+embedding.
   - language detect + авто-перевод в RU.

3. **Legal/Compliance:**
   - хранить source URL, timestamp, rights notes.
   - whitelist доменов и согласованная ToS-политика.

4. **Data Consistency (match stats):**
   - ежедневная сверка результатов между primary и backup API.
   - reconciliation-job для расхождений.

## 7) Ключевой вывод

Для надежного перезапуска проекта: **новости вести через RSS-first модель**, **результаты матчей через специализированные API**, а **HTML scraping держать как ограниченный fallback**. Для России обязательно заложить больше резервов по источникам и мониторингу, так как локальные редакционные потоки критичны для RU-аудитории.
